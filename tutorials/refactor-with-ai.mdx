title: "Refactor Code with AI: Plan, Code, and Review in Shape"

---

Shape's AI Chat gives you two modes purpose-built for refactoring: **Plan** maps out the work and saves a structured plan file; **Code** implements it and proposes file changes you review before they are applied. This tutorial walks you through a safe, reviewable refactor — extracting a repeated utility, updating all call sites, and verifying nothing broke.

**Prerequisites:** A Shape account (sign in from the avatar menu), a project open in Shape, and an AI Chat panel open.

---

<Steps>
  <Step title="Prepare your workspace">
    Open your project in Shape. Sign in to your Shape account from the **avatar menu** in the title bar if you have not already — AI features require an active session.

    Open AI Chat from the title bar or press **Ctrl+L**.
  </Step>

  <Step title="Plan the refactor (recommended for larger changes)">
    Switch to **Plan** mode in the AI Chat mode switcher.

    Describe what you want to refactor and which files are involved. For example:

    ```
    I have inline toLocaleDateString calls scattered across components/. 
    I want to extract a formatDate utility into lib/format-date.ts and 
    replace all inline calls with imports from that module.
    ```

    Send the message. The assistant produces a structured plan and saves it to `.shape/plans/` in your project. Open the plan file, read through it, and edit any steps that are inaccurate before continuing.

    <Note>
      Planning is optional for small, well-understood changes. Use it whenever the refactor touches many files or has dependencies you want to think through first.
    </Note>
  </Step>

  <Step title="Run the implementation in Code mode">
    Switch to **Code** mode. Send a precise instruction — the clearer you are, the fewer follow-up corrections you will need. For example:

    ```
    Create lib/format-date.ts with a formatDate function that wraps 
    toLocaleDateString. Replace all inline toLocaleDateString calls in 
    components/ with imports from the new module. Do not change any 
    unrelated files.
    ```

    The AI proposes edits to the relevant files and adds them to the pending strip above the chat input.
  </Step>

  <Step title="Review each changed file">
    Click each file in the pending strip to open a diff tab. Read the added lines (green) and removed lines (red) carefully.

    - Click **Keep** if the change is correct and in scope.
    - Click **Undo** to reject an out-of-scope or incorrect change.

    Work through every file before moving on — you are in full control of what gets applied.
  </Step>

  <Step title="Verify the changes">
    Once you have reviewed and kept the edits you want:

    1. Save all files with **Ctrl+K S**.
    2. Open the Problems panel with **Ctrl+Shift+M** and fix any TypeScript or ESLint errors.
    3. Open the terminal (**Ctrl+`**) and run your test suite:

       ```bash
       npm test
       ```

    4. If the AI suggests a terminal command (for example to run tests), it appears as a **Run** card in the chat. Click **Run** to approve and execute it.
  </Step>

  <Step title="Iterate on failures">
    If a test fails, describe the failure in the same chat thread. The AI maintains context from the previous turn, so you can be specific:

    ```
    The test in format-date.test.ts fails because of a timezone offset. 
    Fix the test to use UTC instead of local time.
    ```

    Review the proposed fix and keep or undo as before.
  </Step>
</Steps>

## What You Learned

<CardGroup cols={2}>
  <Card title="Plan before you code" icon="map">
    Use Plan mode to design the refactor and save a reference document to `.shape/plans/` before writing a single line.
  </Card>
  <Card title="Code mode for implementation" icon="code">
    Switch to Code mode with a precise instruction to generate file edits across your entire codebase.
  </Card>
  <Card title="Keep and Undo per file" icon="check">
    Review every diff in the pending strip and accept or reject changes file by file — you approve what lands in your repo.
  </Card>
  <Card title="Verify with Problems and tests" icon="flask">
    Use the Problems panel and your test suite to confirm correctness before committing.
  </Card>
</CardGroup>

<Tip>
  After a successful refactor, commit the changes with an AI-suggested message — click the **sparkle icon** in the Source Control panel's commit message field.
</Tip>
