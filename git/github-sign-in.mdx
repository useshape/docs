Shape has a dedicated GitHub sign-in separate from your Shape account. Connecting it lets you push and pull from GitHub repositories without entering credentials every time, and unlocks pull requests, Actions, and CI checks inside the Git Manager window.

<Note>
Local Git operations — staging, committing, viewing history — work without signing in to GitHub. You only need to sign in when interacting with GitHub remotes or the Git Manager.
</Note>

## When You Need to Sign In

You'll need a connected GitHub account to:

- Push commits to a GitHub HTTPS remote without password prompts
- Pull from a private GitHub repository
- Open pull requests, Actions, and checks in the Git Manager
- See your GitHub username and avatar in the titlebar menu

## Sign In to GitHub

<Steps>
  <Step title="Open the account menu">
    Click your **avatar** in the titlebar (top-right corner of the window).
  </Step>
  <Step title="Start the sign-in flow">
    Under the **GitHub** section, click **Sign in with GitHub**.
  </Step>
  <Step title="Authorize in your browser">
    Your default browser opens a GitHub OAuth page. Approve the authorization request.
  </Step>
  <Step title="Return to Shape">
    Switch back to Shape. The avatar menu now shows **@yourusername** under the GitHub section.
  </Step>
</Steps>

Shape stores your credentials using the Git credential helper on Windows, so you won't be prompted again for HTTPS operations on github.com remotes.

## Sign Out of GitHub

Click your **avatar** in the titlebar, then under **GitHub** click **Sign out**. This clears your remote authentication credentials only — your local repository and commit history are not affected.

## Prerequisites

Shape's GitHub sign-in requires either **Git for Windows** or the **GitHub CLI** to be installed on your system. If neither is present, the avatar menu displays a note explaining what to install. Once installed, restart Shape and the sign-in option becomes available.

## Troubleshooting

<Accordion title="Sign-in fails or browser doesn't redirect back">
  Confirm you approved the OAuth request on GitHub's authorization page. Check that your network connection is active and that no firewall or proxy is blocking the OAuth callback. Close the browser tab and retry from **avatar → GitHub → Sign in with GitHub**.
</Accordion>

<Accordion title="Push still asks for credentials after signing in">
  Verify that your remote URL points to `github.com`. Open the Source Control sidebar, check your remote URL in the remote dialog, and confirm it begins with `https://github.com/`. If it does, sign out and sign back in to refresh the stored credential.

  SSH remotes (`git@github.com:...`) bypass Shape's credential helper entirely — configure SSH keys in your system's SSH agent outside of Shape.
</Accordion>

<Accordion title="Signed in as the wrong GitHub account">
  Click **avatar → GitHub → Sign out**, then sign back in with the correct account. If the wrong credentials persist, your system's Git credential manager may have cached them. Open **Windows Credential Manager**, find the stored `github.com` entry, remove it, and sign in again from Shape.
</Accordion>

<Accordion title="Git Manager shows empty pull requests or Actions">
  Confirm two things: you are signed in to GitHub (avatar menu shows `@username`), and the folder you have open contains a repository whose remote URL points to GitHub. If the remote is on a different host, the Git Manager won't populate GitHub-specific data.
</Accordion>
