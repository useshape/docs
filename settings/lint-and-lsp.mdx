Shape ships with a full suite of language tooling for web projects — no separate installs required. You control each piece independently from **Settings → Features**. ESLint and Prettier share one section; individual language servers each have their own toggle.

## ESLint

Go to **Settings → Features → ESLint & Prettier** to configure linting.

| Setting | Description |
|---|---|
| **Enable ESLint** | Runs ESLint on supported files and shows errors in the editor gutter and Problems panel. |
| **Fix on save** | Applies all auto-fixable ESLint rules whenever you save a file. |

<Note>
  Shape reads your project's ESLint config automatically — `.eslintrc`, `.eslintrc.js`, `eslint.config.js`, and other standard locations. You do not need to point Shape at a config file manually.
</Note>

## Prettier

Prettier settings live in the same **ESLint & Prettier** section.

| Setting | Description |
|---|---|
| **Enable Prettier** | Registers Prettier as the document formatter for supported file types. |

When Prettier is enabled:

- **Format Document** (**Alt+Shift+F**) uses Prettier.
- **Format on save** (under **Settings → Editor**) uses Prettier when you save.
- Shape reads your project's `.prettierrc`, `prettier.config.js`, or `package.json` `"prettier"` key automatically.

## Language Servers

Go to **Settings → Features → Language Servers** to toggle individual servers. Disabling a server stops both diagnostics and code completions for that language.

| Language Server | File Types | Features |
|---|---|---|
| **TypeScript** | `.ts`, `.tsx`, `.js`, `.jsx` | Type checking, completions, hover docs, go-to-definition |
| **CSS** | `.css`, CSS Modules | Property completions, value suggestions, lint |
| **HTML** | `.html` | Tag completions, attribute suggestions, validation |
| **JSON** | `.json`, `.jsonc` | Schema validation, key/value completions |
| **Tailwind CSS** | Any file with Tailwind classes | Class completions, hover previews |
| **Emmet** | HTML and CSS files | Abbreviation expansion (e.g. `div.container>ul>li*3`) |

## Node.js Package IntelliSense

Go to **Settings → Features → Node.js** and enable **Coding assistance** to get import path completions for npm packages. Shape reads your `node_modules` directory and suggests package names and their exported members as you type import statements.

<Note>
  Design tooling — Tailwind scrubbing, design autocomplete, and design diagnostics — is configured separately under **Settings → Editor → Design**, not in the Language Servers section.
</Note>

## Troubleshooting Language Tooling

<Accordion title="Completions or diagnostics are not appearing">
  1. Open **Settings → Features → Language Servers** and confirm the relevant server is toggled on.
  2. Press **Ctrl+Shift+M** to open the Problems panel and look for any errors that may be silent in the editor.
  3. Open the **Output** panel and select the language server from the dropdown to read its startup logs.
  4. Confirm your project has the expected config file — `tsconfig.json` for TypeScript, an ESLint config for linting, and so on.
  5. Re-open the project folder (**File → Open Folder**) to restart the language servers.
</Accordion>

<Accordion title="Prettier is not formatting on save">
  Confirm that both **Enable Prettier** (under ESLint & Prettier) and **Format on save** (under Editor) are turned on. If a project-level `.prettierrc` contains a syntax error, Prettier will silently skip formatting — check the Output panel for Prettier errors.
</Accordion>

<Accordion title="ESLint errors are not auto-fixed on save">
  Ensure **Fix on save** is enabled. Not every rule is auto-fixable — rules without a fixer will still appear in the Problems panel even after save.
</Accordion>
