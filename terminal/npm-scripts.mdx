When your project has a `package.json` with defined scripts, Shape surfaces a **Scripts** dropdown in the titlebar. You can start your dev server, run a build, or trigger a lint check with a single click — no need to type `npm run` commands manually.

## Run a Script

<Steps>
  <Step title="Open a project with scripts">
    Open a folder that contains a `package.json` at the root with at least one entry in the `scripts` object. The **Scripts** button appears in the titlebar automatically.
  </Step>
  <Step title="Click Scripts in the titlebar">
    Click the **Scripts** button to open the dropdown list of available scripts.
  </Step>
  <Step title="Select a script">
    Click any script — such as `dev`, `build`, or `lint`. Shape runs `npm run <script>` (or the equivalent for your package manager) in the integrated terminal and opens the bottom panel if it was hidden.
  </Step>
</Steps>

## Package Manager Detection

Shape automatically detects which package manager your project uses by checking for lockfiles in the project root:

| Lockfile | Package manager used |
|----------|---------------------|
| `bun.lock` | Bun |
| `pnpm-lock.yaml` | pnpm |
| `yarn.lock` | Yarn |
| `package-lock.json` | npm |

If Shape picks the wrong one, or if you use a setup that doesn't rely on a lockfile, override it via the **Package Manager** setting in Settings.

## Script Output

Each script runs in its own terminal tab. Standard output and errors appear there in real time:

- **Short-running scripts** (e.g., `build`, `lint`) — the tab stays open after the process exits so you can review the output.
- **Long-running scripts** (e.g., `dev`) — the process runs until you stop it. Press **Ctrl+C** in the terminal tab to send an interrupt signal and stop the server.

## When the Scripts Button Doesn't Appear

The **Scripts** dropdown only shows up when all three conditions are met:

1. A folder is open in Shape
2. A `package.json` exists at the root of that folder
3. The `scripts` object in `package.json` has at least one entry

<Tip>
Working in a monorepo where scripts live in subpackage directories? Use the integrated terminal to navigate to the specific workspace folder and run scripts there with `npm run` or your package manager's workspace commands.
</Tip>
