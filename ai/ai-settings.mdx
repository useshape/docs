All agent behavior is configured in **Settings → Agents**. Open it from the activity bar gear icon, through **Window → Settings**, or with `Ctrl+,`.

## Models

**Enabled models** — toggle which models appear in the chat mode picker. Disable any model you don't use to keep the dropdown clean.

**Default model** — the model pre-selected for every new chat thread. Set this to whatever you reach for most often so you don't have to change it each time.

## Auto-Run Mode for Terminal Commands

The auto-run setting controls whether the agent needs your permission before running terminal commands:

| Setting | Behavior |
|---|---|
| **Ask every time** | Every command shows a **Run / Reject** card before executing |
| **Auto (safe commands)** *(default)* | Common safe commands run without a prompt; Shape asks before anything destructive |
| **Run everything** | All commands run automatically, except hard-blocked ones |

**Protect destructive Git** is on by default. Commands like `git reset`, `git clean`, `git restore`, and any force-push always require your confirmation, even when **Run everything** is enabled. You can toggle this setting in **Settings → Agents**.

## Edit Controls

Two settings govern how file edits are handled. They are independent — you can enable either, both, or neither.

<Tabs>
  <Tab title="Require Edit Approval">
    **Gates each write before it happens.**

    When enabled, the agent shows an approval card before writing any file. The card shows the filename, `+/-` line counts, and an expandable diff. Press `Ctrl+Enter` to accept or click **Skip** to discard that edit.

    Turn this on when you want to review every proposed change before it touches disk.
  </Tab>
  <Tab title="Auto-Apply Agent Edits">
    **Skips the post-write keep/undo strip.**

    By default, after the agent writes a file, a strip appears in the chat letting you keep or undo the change. Enabling **Auto-apply** skips that strip — edits land silently.

    Turn this on when you trust the agent's output and prefer a cleaner chat experience.
  </Tab>
</Tabs>

## Review Mode: Adversarial Review

When using [Review mode](/ai/chat-modes), Shape runs a second **critic pass** after the initial investigation by default. The critic looks for things the first pass may have missed — edge cases, missed security patterns, or incomplete fixes. Disable this in **Settings → Agents** if you prefer a single-pass review.

## Context Settings

| Setting | What it does |
|---|---|
| **Max context lines** | Limits how many surrounding lines of code are sent with each message. Lower this if you want to reduce token usage. |
| **Semantic codebase index** | Builds a semantic index of your project when you open it. Powers the `@codebase` mention and search. Re-index manually after large refactors. |
| **Semantic embeddings** | On by default when signed in. Combines remote semantic search with local keyword search. Turn off to use keyword search only. |

## Custom Rules

The **Rules** field lets you write persistent instructions that shape how the assistant behaves across every message — coding conventions, style preferences, files to avoid, or team-specific patterns.

Rules are appended to the mode's system instructions on every message, so you don't have to repeat yourself.

You can also add a **`.shape/rules.md`** file to your project repository. Shape loads this file automatically alongside your Settings rules, making conventions shareable with your team through Git.

```markdown
# .shape/rules.md example

- Use TypeScript strict mode. Never use `any`.
- All React components must use named exports.
- Tests live in `__tests__/` alongside the source file.
- Do not modify files in `src/generated/`.
```

## MCP Servers

Model Context Protocol (MCP) extends the assistant with external tools — databases, APIs, or any custom tool you build.

<Steps>
  <Step title="Open MCP settings">
    Go to **Settings → Agents → MCP**.
  </Step>
  <Step title="Add a server entry">
    Each entry requires:
    - **Name** — a label for the server
    - **Launch command** — the command Shape runs to start the server
    - **Arguments** — any command-line arguments
    - **Environment variables** — secrets or config values the server needs
    - **Enabled toggle** — enable or disable without deleting the entry
  </Step>
  <Step title="Restart to apply">
    After adding or changing an MCP server config, restart or reconnect the server. The new tools become available to the agent in the next chat thread.
  </Step>
</Steps>

<Note>
MCP servers run as local processes on your machine. Keep any secrets (API keys, tokens) in the environment variables field rather than hardcoding them in the launch command.
</Note>
