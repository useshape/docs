When the AI agent edits files in Code mode (or any other editing mode), Shape gives you explicit control over whether those changes stick. By default, edits land on disk immediately and you review them afterward — but you can also require approval before any file is written.

## Default Flow: Review After the Edit

<Steps>
  <Step title="Agent writes the file">
    The agent edits files directly on disk. Each edit appears in the chat thread as a step with `+` (added) and `-` (removed) line counts.
  </Step>
  <Step title="Review strip appears">
    A strip above the chat input shows all pending edits, with a **Keep** and **Undo** button for each file.
  </Step>
  <Step title="Inspect the diff">
    Click any filename in the review strip to open a diff view in the editor. Lines added by the agent appear in green, removed lines in red.
  </Step>
  <Step title="Keep or undo">
    - **Keep** (or **Keep All**) — dismisses the review strip and leaves the file as written
    - **Undo** (or **Undo All**) — restores the file to its state before the first unresolved edit in this conversation
  </Step>
</Steps>

<Note>
If the agent edits the same file again before you've kept or undone its previous change, the review strip updates to reflect the latest version. Choosing **Undo** at that point always restores back to the original baseline — the state of the file before any unresolved edit in this session.
</Note>

### Skip the Review Strip

If you trust the agent's output and don't want the review step, enable **Auto-apply agent edits** in **Settings → Agents**. Edits are written to disk silently, without showing the keep/undo strip.

## Optional: Require Approval Before Writing

For tighter control, you can gate every file write behind an explicit approval step.

<Steps>
  <Step title="Enable pre-write approval">
    Go to **Settings → Agents** and turn on **Require edit approval**.
  </Step>
  <Step title="Review the approval card">
    When the agent wants to edit a file, an approval card appears in the chat thread showing the filename, `+/-` line counts, and an expandable diff.
  </Step>
  <Step title="Accept or skip">
    - Press `Ctrl+Enter` or click **Accept** to allow the write
    - Click **Skip** to discard that specific edit without stopping the agent
  </Step>
</Steps>

<Note>
Pre-write approval and the post-write keep/undo strip are **independent settings**. You can use one, both, or neither. Approval gates the write itself; keep/undo is a safety net after the fact.
</Note>

## Terminal Command Auto-Run

File edits and terminal commands are controlled separately. Go to **Settings → Agents → Auto-run mode** to choose:

| Setting | Behavior |
|---|---|
| **Ask every time** | Every command shows a **Run / Reject** card before executing |
| **Auto (safe commands)** *(default)* | Common safe commands run without prompting; destructive commands always ask |
| **Run everything** | All commands run automatically except hard-blocked ones |

<Warning>
**Protect destructive Git** is on by default and always asks before `git reset`, `git clean`, `git restore`, and force-pushes — even when **Run everything** is enabled. You can toggle this setting in **Settings → Agents**.
</Warning>

## Session Persistence

Shape tracks which edits you've kept or undone for the duration of the conversation. If you reload Shape, previously resolved edits remain resolved. If the agent later edits the same file again, a new review step opens for those new changes.
