Every message you send in Shape's AI Chat runs in a **mode** that controls what the assistant is allowed to do. Select a mode from the dropdown before sending your message. You can switch modes between messages — earlier context carries over, but the new mode's permissions apply immediately.

## The Five Modes

<Tabs>
  <Tab title="Ask">
    **Read-only. No file edits or terminal commands.**

    Ask is for understanding — not changing — your codebase. Use it to explain what a function does, diagnose an error message, or learn how a system is structured. Because it can't write files or run commands, Ask is completely safe to use at any stage of your work.

    Best for:
    - Learning an unfamiliar codebase
    - Explaining errors or stack traces
    - Answering architecture questions before you start coding
  </Tab>
  <Tab title="Code">
    **Read, edit files, and run terminal commands.**

    Code is the default mode for implementation tasks. The agent searches your repo, edits files, and runs tests or linters. Every file edit shows as a reviewable step with `+/-` line counts. You can keep or undo edits after they land. See [Reviewing Edits](/ai/reviewing-edits) for the full review workflow.

    Best for:
    - Implementing features or fixing bugs
    - Refactoring across multiple files
    - Running and fixing failing tests
  </Tab>
  <Tab title="Plan">
    **Research only. Writes a markdown plan — no source edits.**

    Plan mode investigates your codebase and produces a structured plan saved to `.shape/plans/`. The plan includes a `## Todos` checklist of concrete steps. No source files are touched.

    When you're ready to execute, send **"Build this plan"** or switch to Code mode. During build, the assistant maintains a live todo checklist in the chat thread.

    Best for:
    - Large features that need scoping before any code is written
    - Getting a second opinion on an implementation approach
    - Creating a shared spec for a task
  </Tab>
  <Tab title="Visual">
    **UI and styling focused. Optional in-chat component preview.**

    Visual mode is optimized for frontend work. It reads your existing component library and design patterns before making changes, so suggestions fit your codebase's style. When no component library is detected, it defaults to **Radix + Tailwind**.

    An optional inline preview renders components directly in the chat thread.

    Best for:
    - Building or restyling UI components
    - Iterating on layouts and spacing
    - Applying design system conventions consistently

    <Note>
    Visual mode was called **Design** in older versions of Shape.
    </Note>
  </Tab>
  <Tab title="Review">
    **Systematic investigation of bugs and security issues.**

    Review mode reads errors, logs, and relevant files before suggesting any fix. It actively looks for patterns in authentication, user input handling, and unsafe API usage. By default, a second **adversarial critic pass** runs after the initial review to catch missed issues — you can toggle this in **Settings → Agents**.

    Best for:
    - Debugging hard-to-reproduce issues
    - Security audits before shipping
    - Investigating regressions with unclear root causes

    <Note>
    Review mode was called **Debug** or **Security** in older versions of Shape.
    </Note>
  </Tab>
</Tabs>

## Quick Reference

| Mode | Reads files | Edits files | Runs commands | Best for |
|---|---|---|---|---|
| **Ask** | ✅ | ❌ | ❌ | Questions and explanations |
| **Code** | ✅ | ✅ | ✅ | Implementation and refactoring |
| **Plan** | ✅ | Plan file only | ❌ | Scoping before coding |
| **Visual** | ✅ | ✅ | ✅ | UI and styling work |
| **Review** | ✅ | ✅ | ✅ | Debugging and security review |

## Switching Modes Mid-Conversation

Change the mode in the dropdown at any time. The conversation history — including code the agent has already read or written — carries over into the new mode. Only the tool permissions change.

<Tip>
Start in **Ask** to explore the problem, switch to **Plan** to outline an approach, then move to **Code** to implement. Using modes in sequence gives you checkpoints before any files are modified.
</Tip>
